## Chapter 2: Model Development, Training, and Evaluation Audit Evidence — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | F1 Score formula? | F1 = 2 × (Precision × Recall) / (Precision + Recall). Exam tip: use F1 when you need a balance between false positives and false negatives, especially on imbalanced data. |
| 2 | Precision vs Recall — what does each answer? | Precision = TP/(TP+FP) — 'of predicted positives, how many were correct?' Recall = TP/(TP+FN) — 'of actual positives, how many did we catch?' Exam tip: fraud/medical screening favors recall; spam filtering favors precision. |
| 3 | AUC-ROC value interpretation range? | 0.5 = random guessing, 1.0 = perfect separation, below 0.5 = worse than random (often a labeling/inversion bug). Exam tip: AUC is threshold-independent, unlike F1. |
| 4 | Standard k-fold cross-validation values commonly used in practice? | k=5 and k=10 are the most common defaults, balancing bias/variance and compute cost. Exam tip: small datasets with high k (e.g., leave-one-out) increase variance in fold estimates. |
| 5 | Model Cards for Model Reporting (Mitchell et al., 2019) — key sections? | Model Details, Intended Use, Factors, Metrics, Evaluation Data, Training Data, Quantitative Analyses, Ethical Considerations, Caveats and Recommendations. |
| 6 | Datasheets for Datasets (Gebru et al., 2018) — key sections? | Motivation, Composition, Collection Process, Preprocessing/Cleaning/Labeling, Uses, Distribution, Maintenance. Exam tip: datasheets document the DATA, model cards document the MODEL. |
| 7 | Common experiment tracking tools tested for audit evidence capability? | MLflow (Tracking + Model Registry), Weights & Biases, DVC (data/model versioning), Neptune.ai, TensorBoard. Exam tip: MLflow Model Registry adds stage transitions (Staging/Production/Archived) useful as audit lineage. |
| 8 | MLflow basic logging commands (Python API)? | mlflow.log_param('lr', 0.01); mlflow.log_metric('f1', 0.87); mlflow.log_artifact('model.pkl'). Exam tip: these three calls create the reproducibility trail auditors look for. |
| 9 | Signs of overfitting an auditor should look for in training logs? | Large gap between training and validation/test metrics, near-perfect training score with much lower validation score, high variance across CV folds. Exam tip: request the learning curves, not just final metrics. |
| 10 | Hyperparameter tuning methods — key comparison? | Grid Search (exhaustive, expensive), Random Search (samples randomly, more efficient at scale), Bayesian Optimization (models the search space, sample-efficient). Exam tip: audit evidence should show which method was used and the search space bounds, not just the final chosen values. |
| 11 | Why is model versioning (code + data + environment) required for audit reproducibility? | Without linked versions of training code, dataset snapshot, and environment (e.g., via DVC + Git + Docker/conda lock files), a reported metric cannot be independently reproduced or verified. |
| 12 | Key regulatory/standard references for AI model documentation audits (as of 2026)? | EU AI Act Article 11 (technical documentation for high-risk systems), NIST AI RMF 1.0 (Map/Measure/Manage/Govern functions), ISO/IEC 42001:2023 (AI management system standard). Exam tip: know which artifact (model card, datasheet, tech doc) maps to which requirement. |
