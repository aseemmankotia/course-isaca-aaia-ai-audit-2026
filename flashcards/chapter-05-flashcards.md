## Chapter 5: AI Monitoring, Drift Detection, and Model Performance Assurance — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | PSI (Population Stability Index) interpretation thresholds | PSI < 0.1 = no significant shift; 0.1–0.25 = moderate shift, investigate; > 0.25 = significant shift, retraining review triggered. Exam tip: PSI is the standard metric cited for drift monitoring dashboards. |
| 2 | Data drift vs Concept drift — key differentiator | Data drift = input feature distribution changes, P(Y\|X) unchanged. Concept drift = relationship between inputs and target changes, even if input distribution is stable. Exam tip: check whether accuracy stays constant (data drift) or degrades (concept drift). |
| 3 | KL Divergence vs PSI for drift detection | Both measure distribution difference between baseline and current data. PSI is symmetric with fixed interpretive thresholds; KL divergence is asymmetric and more sensitive to small probability changes, especially in tails. Exam tip: PSI is the more commonly cited operational metric. |
| 4 | Continuous monitoring vs periodic validation | Continuous monitoring = automated, real-time metric tracking with alerting. Periodic validation = scheduled deep-dive testing against a curated holdout dataset. Exam tip: mature governance programs require both — one does not replace the other. |
| 5 | Retraining trigger types | Three trigger types: (1) Scheduled/calendar-based, (2) Performance-threshold-triggered, (3) Drift-triggered. Exam tip: a policy mandating retraining every N months regardless of performance is scheduled retraining. |
| 6 | Minimum audit trail log fields for a production AI model | Model version/ID, input data (or reference), output/prediction with confidence score, timestamp, and any human override/review decision. Exam tip: missing human override logging is a common audit finding. |
| 7 | Human-in-the-loop (HITL) control — purpose | Routes low-confidence, high-risk, or flagged model outputs to a human reviewer before final action is taken. Exam tip: HITL is an active override mechanism, distinct from passive monitoring. |
| 8 | AI incident management — first response step | Log and triage the incident, assessing severity and scope BEFORE any remediation (retraining, rollback, shutdown). Exam tip: skipping triage/documentation is a common wrong-answer trap. |
| 9 | Chi-squared test — when used in drift detection | Used to detect distributional drift in categorical (discrete) features by comparing observed vs expected frequency counts. Exam tip: PSI/KS test = numerical features; Chi-squared = categorical features. |
| 10 | Kolmogorov-Smirnov (KS) test — use case | Non-parametric test comparing cumulative distribution functions of two continuous samples to detect data drift. Exam tip: KS test does not assume a specific distribution shape, unlike parametric tests. |
| 11 | Model performance alerting — design principle | Set alert thresholds based on business-critical KPIs (e.g., recall/precision drop beyond a defined percentage from baseline), not just raw accuracy. Exam tip: exam scenarios test whether the RIGHT metric is monitored for the use case (e.g., recall for fraud detection, not accuracy). |
| 12 | Cost trade-off: continuous monitoring vs periodic validation | Continuous monitoring has higher ongoing compute/infrastructure cost but catches issues faster; periodic validation is cheaper but has detection lag. Exam tip: high-risk/regulated models justify continuous monitoring despite the added cost. |
